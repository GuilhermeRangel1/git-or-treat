## Objetivo e limites

Permitir desenvolver as jornadas sem conhecer o esquema físico da Gold. Uma consulta demonstrável percorre navegador → API FastAPI → serviço → interface de leitura → fonte sintética. As páginas do produto e suas fundações visuais existentes permanecem preservadas; a demonstração fica em `/dev/contratos`, somente no servidor de desenvolvimento, sem item de menu.

A entrega define contratos e exemplos consumíveis de indicadores, receita, busca/resumo da UC, fila e continuidade. Aproveita os contratos existentes de ordens e do serviço de IA; não implementa chat, provedor, SQL, ciclo operacional, carga CSV ou fórmulas oficiais da Gold. Não adiciona tabelas ou migrações. Campos da API são uma proposta de consumo, não afirmações sobre colunas do dataset.

## Arquitetura e alternativas

Adotar fonte sintética em memória no backend, injetada por `Depends`, com registros relacionados e agregações em serviços. A interface de leitura não expõe SQL nem nomes de tabelas Gold. Um futuro adaptador Gold implementará a mesma fronteira; mudanças de semântica serão versionadas explicitamente.

Alternativas: mocks apenas no frontend não exercitam o caminho HTTP completo; semear um banco agora anteciparia o esquema físico ainda desconhecido. A opção em memória reduz dependências e mantém ordens operacionais separadas. O modo sintético é explícito por `ANALYTICS_SOURCE=synthetic`; o padrão `unavailable` retorna indisponibilidade, sem fallback silencioso. Valores desconhecidos da configuração impedem a inicialização.

## Contrato comum de leitura

Preservar as rotas `/api/v1/kpis`, `/revenue`, `/ucs`, `/ucs/{uc_id}`, `/inspections/queue` e `/operations/continuity`. Adotar nomes ingleses no novo corpo tipado, mantendo os parâmetros de consulta portugueses existentes quando pertinentes. Schemas Pydantic e `response_model` publicam contratos no OpenAPI. Respostas analíticas não dependem de conexão PostgreSQL no modo sintético.

Envelope consumido pelo frontend:

```json
{
  "data": {
    "metrics": [{
      "id": "billed_amount",
      "label": "Valor faturado",
      "value": 182.0,
      "unit": "BRL",
      "status": "available",
      "limitations": []
    }]
  },
  "metadata": {
    "contract_version": "1.0.0",
    "status": "available",
    "period": {"start": "2025-01", "end": "2025-02", "granularity": "month"},
    "filters": {"municipio": null, "bairro": null, "classe": null, "alimentador": null},
    "source": {
      "kind": "synthetic", "version": "dev01-v1", "is_demo": true,
      "updated_at": "2026-10-20T00:00:00Z"
    },
    "limitations": ["Dados sintéticos; não constituem diagnóstico da V-Energy."]
  }
}
```

O valor 182 acima exemplifica a forma, não fixa o total da fixture final. O catálogo deve publicar os totais de controle efetivos e exemplos independentes de reconciliação. `value` é número JSON finito ou `null`; cada métrica declara unidade, sem unidade mista no envelope.

Estados por resposta, seção e métrica: `available` (zero válido continua zero), `empty` (sem registros para o recorte, valor ausente), `partial` (cobertura incompleta explicitada) e `unavailable` (fonte/denominador necessário indisponível). Nenhum estado ausente é convertido em zero. Percentual sem base válida é `null` com motivo. Seções parciais da UC não tornam seu cadastro inexistente.

Filtros comuns: `competencia_inicio`, `competencia_fim` no formato `YYYY-MM`, `municipio`, `bairro`, `classe` e `alimentador`, apenas onde aplicáveis. Defaults demonstrativos: janeiro e fevereiro de 2025. Validar mês real e início ≤ fim, tamanhos das entradas e parâmetros de ordenação; ecoar somente filtros efetivamente aplicados. Recortes conhecidos sem registros são vazios. Combinação geográfica contraditória deve ser rejeitada ou explicitamente documentada como vazia, nunca ignorada.

Listagens usam `data.items` e `pagination` no envelope, com `page` (≥1), `page_size` (1–100), `total` e `total_pages`; ordenação é estável e permitida por lista explícita. Página além do final retorna lista vazia preservando total. Indicadores agregados não são paginados. Busca de UC usa `q` e procura somente identificadores sintéticos, sem documento pessoal. UC inexistente retorna 404.

Erros analíticos têm `error.code`, `error.message` e `error.details` (lista de `{field, message}`): entrada inválida 422, recurso inexistente 404, fonte indisponível 503. Não expor entrada sensível, SQL ou stack. Não alterar contratos operacionais/IA já testados desnecessariamente.

## Dados e definições provisórias

Criar registros determinísticos de cadastro, consumo, fatura, medidor, GD, interrupção, chamado, alimentador e suspeita. As referências UC/alimentador devem existir; fatura e consumo têm grãos independentes. Incluir UC completa, medição zero legítima, UC sem fatura/leitura, cobertura parcial e alimentador sem denominador. Os mesmos registros alimentam os agregados e os detalhes; não manter totais desconectados hardcoded nos endpoints.

Documentar o significado de faturado, pago, energia medida/faturada, preço observado, referência temporal, arredondamento e nulidade. Métodos demonstrativos de preço-volume, DEC/FEC, prioridade e recuperação são provisórios, com referência/versionamento; não generalizar uma estimativa sintética como diagnóstico. Quando não houver dados para um componente, retornar indisponibilidade explícita.

Ordens mantêm os schemas e a persistência atuais; sua implementação completa fica nos cards DEV-06/07. Contratos de perguntas e insights permanecem no serviço `ai-agent`; documentar suas entradas/saídas e como apontar evidência para o futuro lote. Não apresentar `/ai/query` placeholder como executor seguro implementado.

## Frontend de verificação

`/dev/contratos` existe somente quando `import.meta.env.DEV` é verdadeiro, sem navegação de produto. Usa `apiClient`, TanStack Query e tokens existentes. Contém formulário simples de período/município/classe para `/api/v1/kpis`, valores e unidades, estado, fonte, versão, atualização e limitações. Parâmetros aplicados compõem a chave do cache e a requisição aceita cancelamento. A resposta HTTP é validada em execução antes de renderizar. Não há fixture de negócio embutida na interface; fixtures de teste são permitidas.

O aviso de demonstração é obrigatório e a tela distingue carregamento, vazio, parcial, indisponível e erro de contrato/rede. Uma requisição antiga não pode aparecer como resultado de filtros novos. Produção não inclui rota nem carrega a página de diagnóstico. Não é uma nova proposta visual para Panorama.

## Verificação e aceite

Fronteiras de teste: contratos HTTP FastAPI; interações públicas da tela; um fluxo navegador/API real sem interceptar os dados. Conferir totais com literais de controle calculados a partir da fixture documentada, sem repetir a implementação. Testar filtros combinados, período inválido, paginação, zero, vazio, parcial, indisponibilidade e UC inexistente. Rodar os testes anteriores para proteger ordens e IA.

O aceite exige evidência do fluxo real, testes, build e revisão do controlador. Atualizar PRD, guias e catálogo de contratos, preservando os requisitos funcionais pendentes de Gold. Commit/push só são considerados após revisão; merge para `develop` fica para a etapa de integração autorizada.
